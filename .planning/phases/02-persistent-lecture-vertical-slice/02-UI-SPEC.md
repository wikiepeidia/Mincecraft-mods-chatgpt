# Phase 2 — UI Design Contract

> Visual and interaction contract for the discoverable Contract-to-Lecture vertical slice. Generated by gsd-ui-researcher and verified by gsd-ui-checker.

---

## Scope and Experience Goal

Phase 2 must make one complete boss encounter understandable through ordinary Minecraft interaction, without a custom screen or external guide. The player discovers and crafts a Cursed Unpaid Internship Contract, uses it on a lectern that becomes the Internship Desk, understands why an arena is accepted or rejected, learns three spatial attack acts, fails or resumes safely, retries, and recognizes exactly-once victory rewards.

This phase intentionally uses vanilla presentation surfaces and placeholder assets. Bespoke textures, models, sounds, HUD panels, screen-edge effects, journals, and later campaign bosses are deferred. The accepted paper/map appearance is MVP cosmetic debt, not a blocker.

### Required player journey

1. Obtaining paper and ink exposes an advancement/recipe prompt for the Contract.
2. The Contract tooltip explains where and how to use it.
3. Using it on a lectern validates a clear Overworld arena without consuming the item on failure.
4. A valid use establishes the Internship Desk, retry checkpoint, current objective, and Professor encounter.
5. Boss bar, action bar, chat, particle geometry, and distinct sounds teach the three acts.
6. Failure or reload removes encounter-owned presentation and leaves an obvious Retake path.
7. First victory clearly grants the Attendance Sheet entitlement and one Infinite Slides Remote; repeat callbacks never present a duplicate reward.

## Design System

| Property | Value |
|----------|-------|
| Tool | None — native Minecraft/Fabric surfaces only |
| Preset | Not applicable |
| Component library | Vanilla `ServerBossEvent`, action bar, system chat, advancement toast, recipe book, item tooltip, particles, sounds/subtitles |
| Icon library | Vanilla Minecraft item textures and particle shapes; no copied external icons |
| Font | Minecraft default bitmap font; respect the player's GUI scale and Unicode/font settings |
| Renderer | Vanilla-compatible renderer only; no raw OpenGL, custom shader, or phase-specific HUD renderer |

The shadcn gate is not applicable because this is a Minecraft Java/Fabric phase, not a React, Next.js, or Vite interface.

### Presentation hierarchy

| Priority | Surface | Responsibility | Update policy |
|----------|---------|----------------|---------------|
| 1 | World geometry | Shows exactly where danger, safe lanes, quiz pads, and the attendance ring exist | Bounded refresh during telegraph only |
| 2 | Action bar | Shows current attack, required response, and whole-second countdown | At most once per second; replace, never queue |
| 3 | Boss bar | Shows boss identity, health, and current act | Change on health/act transition only |
| 4 | Sound/subtitle | Distinct redundant cue for each mechanic | One onset cue plus bounded result cue |
| 5 | System chat | Preserves objective, quiz prompt/options, failure, recovery, and reward facts | One message group per meaningful transition; no tick spam |
| 6 | Tooltip/recipe toast | Teaches discovery and item use before combat | Static localized copy |

No gameplay truth may exist only in particles, color, sound, or a transient action-bar line.

## Spacing Scale

Declared pixel values apply only if a later implementation needs a small custom overlay; Phase 2 must use vanilla widget layout and must not introduce one merely to use these tokens.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline icon-to-label or glyph spacing |
| sm | 8px | Compact text grouping |
| md | 16px | Default panel/content separation |
| lg | 24px | Major group separation |
| xl | 32px | Safe inset from screen edges |
| 2xl | 48px | Large overlay separation |
| 3xl | 64px | Reserved major-screen spacing |

Exceptions: world-space combat geometry uses Minecraft blocks, not pixels. The locked geometry is a 17×17 validated boundary, 15×15 combat interior, five-block lanes, three fixed quiz zones, and a 2.5-block attendance radius. These are interaction dimensions, not UI spacing-token exceptions.

### World-space layout

The clicked lectern is the Internship Desk. Its facing defines local `forward`, `back`, `left`, and `right`; all player instructions use those local words rather than world compass directions.

- Validate a 17×17 boundary with a 15×15 combat interior, solid floor, four blocks of headroom, loaded chunks, world-border safety, and the exact Overworld dimension.
- Preserve a one-block safety margin around the 15×15 combat interior.
- Never modify or destroy arena blocks by default.
- Persist the lectern position, facing, combat origin, and a bounded nearby retry position.

The coordinate contract is exact. Let `L` be the lectern block position and `F` its horizontal facing toward the arena; local right `R` is `F` rotated clockwise. The arena floor Y is `L.y - 1`, matching the solid support surface under the lectern. The combat-center floor block is `L + 9F - 1Y`. The 17×17 validated boundary contains floor blocks `L + fF + rR - 1Y` for `f = 1..17` and `r = -8..8`. The 15×15 combat interior is the subset `f = 2..16`, `r = -7..7`. Four-block headroom means every interior floor block has passable, non-hazardous blocks at world Y `L.y`, `L.y + 1`, `L.y + 2`, and `L.y + 3`. The lectern remains outside the combat interior and is never replaced.

The retry point is mod-owned campaign data, not a vanilla spawn. First test the feet position two blocks behind the desk, `L - 2F`, then scan a deterministic bounded order behind and beside the lectern out to radius five for a solid support block with two passable player-height blocks and world-border safety. Persist the selected dimension and feet position in campaign state. Never call vanilla bed/respawn setters, never replace the player's bed, and never change their normal death-respawn destination. The saved retry point is used only for Retake placement/recovery and validated retry initiation.

#### Slide Deck lanes

Split the 15-block lateral interior into three contiguous strips:

| Lane | Local right coordinate | Width |
|------|------------------------|-------|
| LEFT | `-7..-3` | 5 blocks |
| CENTER | `-2..2` | 5 blocks |
| RIGHT | `3..7` | 5 blocks |

The safe strip receives an outline plus repeated safe/diamond marks. Each dangerous strip receives an outline plus repeated X marks. Text always names `LEFT`, `CENTER`, or `RIGHT`; color is decorative only.

#### Surprise Quiz pads

Place three fixed answer zones across the arena so their locations never change during the fight:

| Answer | Lateral anchor | Shape identity | Text identity |
|--------|----------------|----------------|---------------|
| A | `right = -5` | Square | `A [SQUARE]` |
| B | `right = 0` | Circle | `B [CIRCLE]` |
| C | `right = 5` | Diamond | `C [DIAMOND]` |

Particle line utilities draw each outline; server-side bounds decide the selected answer. The correct answer is deterministic from encounter seed plus quiz index.

#### Attendance Check ring

Choose one deterministic anchor from four quadrants. Announce it as `FRONT-LEFT`, `FRONT-RIGHT`, `BACK-LEFT`, or `BACK-RIGHT`. Draw one 2.5-block-radius ring and a distinct center mark. Server-side horizontal distance and vertical tolerance decide attendance.

## Typography

Minecraft controls the final rendered size through GUI scale. These values are the semantic source sizes for any text authored by the mod; built-in surfaces remain authoritative.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 9px | 400 | 1.5 | Chat, tooltip body, advancement description |
| Label | 9px | 700 | 1.2 | Action-bar attack name, short item state |
| Heading | 12px | 700 | 1.2 | Advancement title, phase result heading |
| Display | 16px | 700 | 1.2 | Reserved; not used by a custom Phase 2 overlay |

Exactly two weights are allowed: normal 400 and bold 700. Do not encode hierarchy through ALL CAPS alone; uppercase is reserved for short attack/result tokens such as `NEXT SLIDE`, `PRESENT`, and `ABSENT`.

### Copy length limits

- Boss-bar name: target 44 visible characters or fewer.
- Action bar: target 64 visible characters or fewer.
- Combat chat: one fact per line, target 72 characters or fewer.
- Tooltip: at most three instructional lines, target 48 characters per line.
- Quiz: prompt plus three separate option lines; never compress all options into an unreadable paragraph.
- All player-facing copy uses translation keys in `assets/developers_hell/lang/en_us.json`.

At narrow resolution or large GUI scale, built-in Minecraft wrapping is accepted for chat/tooltips. Boss/action copy must meet the limits above so it does not depend on wrapping.

## Color

Phase 2 uses vanilla widgets and the world as its dominant surface; the percentages describe the authored visual emphasis, not a custom flat UI.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Vanilla world + paper ivory `#F2E7C9` | Unchanged arena, paper/map item identity, ordinary readable text |
| Secondary (30%) | Charcoal `#2F343A` | Neutral outlines/background contrast where vanilla rendering permits |
| Accent (10%) | Gold `#D6A11D` with optional teal `#35B8A6` decoration | Yellow boss bar, safe/reward emphasis, advancement highlight, remote cooldown-ready cue |
| Destructive | Red `#B3261E` | Invalid placement, dangerous lane decoration, failure/abort result only |

Accent is reserved for: boss identity/health, safe-lane or correct-answer emphasis, advancement/reward success, and Remote-ready state. It is not applied to every instruction.

Color must never distinguish a correct/safe target by itself. Every semantic color has a text and shape equivalent:

- Safe lane: named direction plus diamond/safe outline.
- Danger lane: named attack plus X marks.
- Quiz choices: A/B/C plus square/circle/diamond.
- Attendance: quadrant text plus ring and bell.
- Error/success: explicit localized sentence plus result sound.

## Component and Surface Contracts

### Advancement and recipe discovery

| State | Contract |
|-------|----------|
| Undiscovered | No intrusive UI. Obtaining obvious paper/ink ingredients satisfies the local advancement criterion. |
| Discovered | Toast title `A Suspicious Opportunity`; description `Craft the contract. It has absolutely no benefits.`; recipe becomes visible locally. |
| Crafted | Contract tooltip remains sufficient to start without an external wiki or command. |

Use singular 26.2 data directories such as `data/developers_hell/recipe/` and `data/developers_hell/advancement/`.

### Contract tooltip and Internship Desk

Required tooltip lines:

1. `Use on a lectern facing a clear Overworld area.`
2. `Starts Lecture 1: Professor Infinite Slides.`
3. `No blocks are changed by default.`

Using the Contract anywhere except a lectern does not consume it and produces: `Find a lectern. It becomes the Internship Desk.`

Successful activation sends, once:

- `Contract signed. The lectern is now your Internship Desk.`
- `Objective: Pass Professor Infinite Slides.`

Invalid placement must identify the actionable reason, consume nothing, persist nothing, and spawn nothing. Required reason families are wrong dimension, unloaded/outside-border area, non-solid floor, insufficient headroom, unsafe retry point, and already-active encounter.

### Retake Form issuance and recovery

Every cleanup that transitions one active attempt to `RETAKE_READY` creates one logical Retake entitlement keyed by owner UUID plus failed attempt UUID. Exactly one usable Retake Form may represent that entitlement at a time.

1. After campaign state records `RETAKE_READY` and encounter presentation is removed, check for an owner-bound Form in the player's inventory and for the tracked owner-bound fallback item entity.
2. If neither exists and inventory insertion succeeds, issue exactly one Form and send `Retake Form issued. Use it on the Internship Desk.`
3. If inventory insertion fails because inventory is full, place exactly one owner-bound fallback Form at the persisted retry point, track its entity UUID in campaign data, and send `Inventory full: Retake Form placed at your retry point.`
4. Duplicate cleanup callbacks for the same attempt find the existing entitlement/Form reference and issue nothing.
5. If the Form and tracked fallback are both missing while state is `RETAKE_READY`, the owner may use the same Internship Desk with an empty hand. This performs the same inventory-first, retry-point-fallback issuance and sends `Retake Form recovered. Use it on the Internship Desk.` or the inventory-full copy above.
6. Empty-hand desk use while a Form or tracked fallback already exists sends `Retake Form already available.` Empty-hand use in any state other than `RETAKE_READY` sends `Nothing to retake.`
7. Using the owner-bound Form on the matching Internship Desk validates the arena and active-state preconditions again. Consume the Form and clear the entitlement/fallback reference only after the retry encounter transition succeeds. A rejected retry consumes nothing.

The fallback item must be identifiable as belonging to this owner/attempt and must not become a duplication path for another player. If the tracked fallback unloads, despawns, or is destroyed, campaign state may clear that physical reference and allow empty-hand recovery of one replacement; it never allows two concurrently tracked Forms for the same entitlement.

### Boss bar

Use one `ServerBossEvent` with `YELLOW` and `PROGRESS`:

- `Professor Infinite Slides | Act 1/3`
- `Professor Infinite Slides | Act 2/3`
- `Professor Infinite Slides | Act 3/3`

The bar appears only for the participant while the encounter is valid. It is hidden and removes all players on victory, failure, abort, disconnect cleanup, dimension change, timeout, reload-to-retake cleanup, and orphan rejection.

### Action bar

Update only on whole-second countdown changes or attack/recovery transitions. Required patterns:

- `NEXT SLIDE [5] - SAFE: LEFT`
- `SLIDE SWEEP - HOLD LEFT`
- `PROJECTOR COOLDOWN - ATTACK!`
- `SURPRISE QUIZ [8] - PICK A / B / C`
- `ANSWER LOCKED: B - ATTACK!`
- `ATTENDANCE [6] - ENTER FRONT-RIGHT RING`
- `PRESENT - ATTACK!`
- `ABSENT 1/3 - three means detention`
- `Lecture restored - next attack in 3 seconds.`

### System chat

Chat preserves information that a player may need after the transient action bar disappears:

- Current objective at encounter start.
- Quiz prompt and one line per A/B/C option.
- Invalid arena reason and next action.
- Failure reason, cleanup confirmation, and Retake instruction.
- Reload cleanup and Retake availability.
- Victory entitlement and first-time practical reward.
- Artifact recovery result.

Dialogue is deduplicated by transition/encounter ID. It never emits every tick or repeats the same line on a duplicate callback.

### Particle geometry

Particles visualize geometry but never own collision or damage. Normal mode may refresh essential outlines every four ticks; reduced-effects mode refreshes only corners/segments and shape marks every ten ticks. Both modes preserve the same server-side bounds.

Hard constraints:

- Send only to the participating/tracking player where practical.
- Cap particles per refresh and helper lifetime per encounter.
- Stop emission immediately on cleanup.
- No full-screen particle curtain, forced particle setting, or ambient particle loop outside a telegraph.
- Critical geometry remains understandable from text and stable shape even if the player's particle setting is minimal.

### Sound and subtitles

Use distinct vanilla sounds so existing subtitle resources remain available:

| Event | Preferred vanilla sound | Text redundancy |
|-------|-------------------------|-----------------|
| Slide wind-up | `BOOK_PAGE_TURN` | `NEXT SLIDE` plus named safe lane |
| Quiz starts/counts | Note-block pling/hat family | Prompt, A/B/C lines, countdown |
| Attendance starts | `BELL_BLOCK` | Named quadrant ring and countdown |
| Correct/present | `VILLAGER_YES` or experience pickup | `ANSWER LOCKED` / `PRESENT` |
| Wrong/absent | `VILLAGER_NO` | Explicit wrong/absent count |

Sound category should make sense for hostile encounter cues and respect player volume controls. No gameplay step depends on hearing a sound.

### Infinite Slides Remote interaction and cooldown

The Remote is activated by ordinary use in either hand while aiming into the world. A successful server-authoritative use projects one short bounded knockback slide in the player's look direction, plays one visible/sound cue, starts exactly 400 ticks (20 seconds) of server-owned cooldown, applies Minecraft's native item-cooldown overlay to every matching Remote stack for that player, and sends `Infinite Slides Remote fired - cooldown 20s.`

Cooldown state survives death, save/quit, and reload in mod-owned player/campaign data. On join or respawn, reapply the native cooldown overlay for the persisted remaining ticks. Remaining time advances only while the logical server is running; it never follows a wall clock while logged out.

| Remote state | Player use | World effect | Native overlay | Action-bar/sound feedback |
|--------------|------------|--------------|----------------|---------------------------|
| READY | Use in either hand | Emit one bounded knockback slide, then enter COOLDOWN | Start full 20-second radial cooldown overlay | `Infinite Slides Remote fired - cooldown 20s.` plus one activation cue |
| COOLDOWN | Use again | No knockback, particles, target scan, or cooldown reset | Continue existing overlay | `Remote recharging - {seconds}s remaining.` using ceiling division of ticks; at most once per attempted use |
| COOLDOWN after join/respawn | No use required | No effect | Restore overlay to persisted remaining fraction | No repeated chat; overlay is sufficient |
| Transition to READY | Cooldown reaches zero | No automatic world effect | Overlay disappears | Exactly once: `Infinite Slides Remote ready.` plus one short ready cue |
| Item absent | Cooldown reaches zero | No effect | No visible stack overlay | Keep server state READY; show feedback only when a Remote is present/selected, avoiding ambient spam |

The ready event is edge-triggered once per cooldown and is not repeated each tick. Selecting or hovering the item exposes `Cooldown: 20 seconds.` in its tooltip. The native overlay is the primary continuous indicator; rejected-use remaining time and the edge-triggered ready line are text redundancies for players who cannot distinguish the overlay visually.

## Act Interaction Contracts

### Act 1 — Slide Deck

1. Enter a roughly five-second Standard wind-up.
2. Boss bar already names `Act 1/3`; action bar names `NEXT SLIDE`, countdown, and safe lane.
3. Safe strip shows safe/diamond marks; the other two show X marks and danger outlines.
4. On impact, the server checks player position against the recorded safe strip.
5. A hit applies bounded damage and a short readable Information Overload consequence.
6. Never implement nausea, forced camera movement, or the deferred unreadable screen-edge bullet overlay.
7. Impact is followed by a short Projector Cooldown damage window with explicit `ATTACK!` text.

### Act 2 — Surprise Quiz

1. Enter an approximately eight-second Standard response window.
2. Send one localized absurd question plus A/B/C option lines to chat.
3. Action bar shows response countdown; particle geometry shows square/circle/diamond pads in fixed locations.
4. Server determines the chosen zone at lock time and compares it with the deterministic correct choice.
5. Correct answer opens a damage window and announces which answer locked.
6. Wrong/no answer produces at most one bounded Homework add and a readable Needs More Reading consequence; it is not lethal.

### Act 3 — Attendance Check

1. Enter an approximately six-second Standard response window.
2. Ring a bell, draw one quadrant ring, and announce its local direction.
3. Server checks the recorded circle bounds at lock time.
4. Success announces `PRESENT` and opens the final damage window.
5. Failure announces `ABSENT n/3`; the third absence may cause bounded detention damage but never instant death.

### Difficulty and reduced presentation seam

Phase 2 defaults to Standard. Timings, damage, add cap, hint strength, particle density, and recovery duration must be configuration-backed/bounded so Story, Relaxed, and Intense can be completed later without rewriting UI. Difficulty never changes jokes or rewards.

Reduced flashing defaults on. Reduced effects removes decorative density, not attack names, countdowns, outlines, shape identities, sounds, recovery windows, or server collision bounds. There is no forced camera shake, nausea, full-screen flash, rapid glow toggle, or strobe in either mode.

## Accessibility and Motion

Every harmful mechanic must provide:

1. Attack name.
2. Required response in text.
3. Affected geometry or target shape.
4. Non-color-only direction/symbol.
5. Distinct sound with existing subtitle support.
6. Wind-up and recovery/damage window.

Additional constraints:

- Critical text remains readable with sound muted and particles minimal.
- Critical geometry remains logically resolvable with color-vision deficiency because text and shapes carry meaning.
- Player particle settings are respected; do not force decorative density.
- No camera shake, nausea, motion blur, rapid full-screen change, strobe, or surprise instant damage.
- Countdown changes occur at whole-second cadence, not every tick.
- Chat queues are bounded and deduplicated; important objective/failure/reward lines remain readable after combat.
- Standard telegraphs are approximately five seconds for Slide Deck, eight for Quiz, and six for Attendance; tuning may vary only within validated difficulty bounds.
- The third Attendance failure cannot instantly kill the player.

## Client/Common Boundary

The logical server owns configuration, recipe/interaction validation, arena axes, encounter state, deterministic choices, boss health/phases, collision, damage, cooldowns, persistence, cleanup, reward ledger, particles, sound dispatch, boss bar, action bar, and system messages.

Common-side implementation may use the compile-checked Minecraft 26.2 surfaces:

- `ServerPlayer.sendOverlayMessage(Component)`
- `ServerPlayer.sendSystemMessage(Component)`
- `ServerBossEvent(UUID, Component, BossBarColor, BossBarOverlay)`
- `ServerBossEvent#setProgress`, `setName`, `addPlayer`, `removePlayer`, `removeAllPlayers`, `setVisible`
- `ServerLevel.sendParticles(...)`
- `Level.playSound(...)`
- `Item.appendHoverText(ItemStack, TooltipContext, TooltipDisplay, Consumer<Component>, TooltipFlag)`

Client code is limited to registering the chosen vanilla-compatible boss renderer if the stable custom entity requires it. It never chooses answers, detects safe zones, advances phases, deals damage, grants rewards, or decides cleanup.

Do not depend on directly mutating vanilla `Display.TextDisplay` or `Display.BlockDisplay` for this slice: their useful setters are private in the cached 26.2 classes. Particle line/shape utilities plus built-in text surfaces are the required MVP path. Do not add a per-tick presentation packet; use vanilla state or one bounded cue per transition.

## Verification Contract

### Automated truths

- Geometry tests prove lane partitions cover the 15×15 interior without overlap/gaps and each chosen safe lane matches damage resolution.
- Quiz tests prove A/B/C positions and square/circle/diamond identities are stable and the correct answer is deterministic from seed/index.
