## Decisions Made

- Progression flags are the durable authority. Reward stacks are outputs, not evidence that a clear happened.
- `/bossrush status` reads a snapshot only. It cannot normalize or mutate an active fight.
- Inventory absence never authorizes re-minting. This closes a drop/store/start duplication path at the cost of deferring physical-loss recovery.
- The deadline build uses vanilla entities and supported server APIs only; no custom renderer, texture, audio, GUI, API, account, telemetry, or network feature was added.

- **Fix:** Status now returns an immutable snapshot; normalization remains on actual recovery/start/abort paths.

### Deadline Deviations and Deferred Risks

- **Physical reward recovery remains deferred.** Exactly-once progression prevents duplication, but a reward lost after issuance is not re-created. A future fix needs a durable delivery/custody ledger, not an inventory-presence heuristic. This leaves the recovery clause of CAMP-05 partial.
- **Vanilla base loot is not guaranteed empty.** Owned mobs suppress XP, pickup, and equipped-item drop chances, but direct vanilla entity types expose no per-instance empty loot table. A custom no-loot entity type was deliberately excluded from the deadline build.
- **Terminal/showcase UI remains deferred.** Sponsor/Codex start and replay are command-driven; Approved Revision Stamp insertion, a replay page, showcase media, and the broader Phase 4/5 loops were not implemented.
- **Accessibility polish is partial.** Server text, particles, named entities, boss bars, bounded wind-ups, and recovery windows exist, but distinct custom audio and human validation of readability remain pending.

**Total auto-fixed deviations:** 3 (2 correctness bugs, 1 blocking verifier update). No deadline-expanding feature work was added.
